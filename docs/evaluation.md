# 1 评测方法

## 1.1 数据集

首个校准集需要 30 个匿名真实任务，发布集需要 150 个固定输入与固定验收规则的匿名任务

仓库只包含合成格式示例，真实任务需要在私有环境导入并完成路径、账号、凭据和个人信息清理

## 1.2 运行矩阵

- Luna low
- Luna medium
- Terra medium
- Sol high
- 自动策略

## 1.3 指标

| 指标               | 计算方式                                   |
| ------------------ | ------------------------------------------ |
| `pass@1`           | 首次执行直接通过的任务数除以总任务数       |
| 显式重跑接受率     | 一次人工确认重跑后通过的任务数除以总任务数 |
| 改派率             | 使用不同模型重新发起的任务数除以总任务数   |
| 人工修正率         | 需要人工修改最终内容的任务数除以总任务数   |
| 每合格结果 Credits | Codex Credits 总量除以最终合格任务数       |
| 延迟               | 分别记录 p50 与 p95                        |

表 1.1 核心评测指标

## 1.4 发布门槛

Luna 默认任务族要求 `pass@1 ≥ 97%`、显式重跑接受率 `≥ 99%`、改派率 `≤ 15%`、人工修正率 `≤ 2%`

每合格结果 Credits 必须 `≤ Terra 基线的 60%`

并发按照 `1 → 2 → 4` 逐级测试，每级运行 50 个混合任务，候选级别继续运行 24 小时与 150 个任务稳定试验

认证损坏、跨线程事件和任务丢失必须为 0
